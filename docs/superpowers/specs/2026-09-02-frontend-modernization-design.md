# image-bed 前端安全加固与现代化重构设计

日期：2026-09-02
状态：已获用户确认，待书面审阅

## 目标

在不改变 EdgeOne Pages 静态部署方式和 Cloud Functions API 契约的前提下，完成两项工作：

1. 修复前端已确认的安全性、输入校验和异步状态恢复问题。
2. 将前端重构为“明亮空气感”的现代 Apple 官网式体验，同时保留现有图床核心功能。

## 设计方向

采用明亮空气感视觉语言：浅灰渐变背景、大留白、清晰的排版层级、轻量半透明导航和卡片、克制的蓝色强调色。首页以上传为唯一主操作，登录提示、上传区和结果反馈保持明确层级。图片库采用舒展的 Masonry 展示，操作按钮在悬停和键盘聚焦时出现。设置、删除确认和错误反馈统一使用卡片式 Modal/Toast。

保留 GitHub 登录、批量上传、剪贴板粘贴上传、图片压缩与进度、图片库分页和排序、复制 URL/Markdown、Lightbox、单图删除、批量删除、背景图、额度设置等能力。

## 技术架构

继续使用原生 ES Modules，不引入构建工具或前端框架，确保 EdgeOne 可直接部署。

- `app.js`：启动入口、事件绑定和模块协调。
- `modules/api.js`：统一 API 请求封装。
- `modules/state.js`：应用状态、缓存常量和主题状态。
- `modules/auth.js`：登录态加载、账户菜单、退出登录。
- `modules/upload.js`：拖拽、粘贴、压缩、上传进度和失败恢复。
- `modules/gallery.js`：图片库、分页、排序、选择和批量删除。
- `modules/lightbox.js`：大图预览、键盘导航、焦点恢复和单图删除。
- `modules/ui.js`：Toast、确认 Modal、主题切换和通用 DOM 工具。

模块之间通过显式函数参数和有限的共享状态通信，避免继续扩大隐式全局逻辑。Cloud Functions 不在本次重构范围内。

## 安全与可靠性

动态 URL 不再直接拼接到 HTML 属性；统一通过 DOM API 设置 `src`、`href`、`dataset` 或属性。头像、图片地址和背景图仅接受允许的 HTTPS URL，Markdown 文本在复制和显示边界安全处理。

每日上传上限和单张文件大小在提交前执行非空、有限数字和合法范围校验，并显示字段级错误。上传主流程使用 `try/finally`，无论压缩、网络请求或渲染发生何种异常，均恢复上传标记、进度条、按钮和状态文本。

登录初始化期间显示加载占位，服务端确认前不渲染完整的登录账户状态。Hero 缓存增加 TTL 清理和条目/大小上限；缓存清理失败在开发环境提供可诊断日志。批量删除以多行、可读的汇总信息反馈成功和失败项。Toast 区分普通和错误提示，错误提示显示更长时间并支持换行。

## 主题系统

提供 `system`、`light`、`dark` 三态主题。默认使用 `system`，由 `prefers-color-scheme` 决定实际颜色；`light` 和 `dark` 覆盖系统偏好。主题选择持久化于 `localStorage`，并在页面初始化早期应用，减少闪烁。设置界面可在三态之间切换。

## 可访问性与响应式

保留语义化 `header`、`nav`、`main`，补充必要的 ARIA 标签、按钮状态和图片替代文本。确认框和 Lightbox 打开时转移焦点，关闭后恢复触发元素；键盘支持 Escape、方向键和 Tab 循环。尊重 `prefers-reduced-motion`。

后端目前只保证单一图片 URL 时，使用安全的 `src` 兼容渲染，不伪造不存在的 WebP 或多尺寸地址。若数据中存在缩略图和可选格式 URL，则以真实返回值生成响应式图片。

## 验证

- `npm run check` 通过。
- `npm test` 至少覆盖 URL 校验、数值校验、主题状态和关键上传状态恢复，不再为 0 个测试。
- 手动验证登录、上传、批量上传、粘贴上传、图片库分页/排序、复制、Lightbox、单图删除、批量删除、背景设置、主题切换和移动端布局。
- 不修改 Cloud Functions API 请求路径、字段和响应契约。

## 非目标

本次不引入 Vue、React、Vite 或其他构建链；不实施 Service Worker、完整国际化、状态管理库或后端图片变体生成。它们可在后续迭代中单独规划。
