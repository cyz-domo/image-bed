实施三项安全修复，并保持现有 API/状态字段兼容：

1. OAuth origin 固化
- 修改 `cloud-functions/_lib/auth.js` 的 `publicOrigin`：优先读取并严格解析 `PUBLIC_BASE_URL`，要求绝对 HTTPS origin（本地开发允许 localhost 回退/显式配置）；生产缺失或非法配置不再信任任意 `Host`/`X-Forwarded-Host`，抛出明确配置错误。
- 修改登录和回调入口，捕获 origin 配置错误并返回 503/配置错误，避免生成不可信 redirect_uri。
- 将 `PUBLIC_BASE_URL` 加入 `cloud-functions/api/health.js` 的必需配置检查。

2. 会话吊销 fail-closed 与可观测注销
- 修改 `readSession`，将吊销名单读取异常转换为可识别错误，而不是放行会话；保留无会话/签名无效/过期返回 null 的行为。
- 在需要认证的 API 入口统一区分“未认证”(401) 与“认证依赖不可用”(503)，至少覆盖 upload、delete、links、settings 等敏感接口，避免故障时误拒绝仍可安全访问的公开接口。
- 修改 logout：吊销写入失败时仍清理浏览器 Cookie，但返回明确的 503/失败 JSON 并保留 no-store，同时让错误进入日志/监控；成功时维持现有响应和单个 `Set-Cookie` 兼容性。

3. 每日上传配额并发安全
- 在 `state.js` 增加配额操作抽象：优先使用 IMAGE_KV 可提供的原子递增/条件能力（兼容常见 `incr`/`increment` 形式），按日期保存计数并设置边界；将“检查+预占”变为一次原子操作，返回 used/remaining。
- 对不支持原子配额操作的存储后端，不继续静默执行不安全的 read-modify-write：上传在需要配额时返回 503，明确提示配额存储不可用；保留状态文件用于吊销/设置等现有功能。
- 上传流程改为校验文件并在真正写 GitHub 前预占额度；GitHub 上传失败时执行补偿递减（若后端支持），补偿失败记录错误；响应使用原子操作返回的剩余额度，不再依赖可能过期的预读值。
- 保持现有 `daily` 状态字段作为兼容/展示数据，并在成功路径同步更新；避免客户端重复重试导致重复扣额时，支持请求幂等键（如 `Idempotency-Key`）或至少为上传预占生成可追踪 reservation key。

4. 验证与文档
- 新增基于 Node 内置 `node:test` 的纯函数/handler 测试，覆盖：非法/缺失 `PUBLIC_BASE_URL` 与恶意 Host、吊销读取失败的 fail-closed、logout 吊销失败状态、配额边界及并发原子调用路径。
- 更新 `package.json` 增加测试脚本；运行 `npm run check` 与测试，检查 diff，确保不破坏现有 cookie、no-store、OAuth 单回调 cookie、私钥兼容行为。
- 更新 README 的必需配置/部署说明，明确 `PUBLIC_BASE_URL` 和原子配额存储要求及故障行为。
